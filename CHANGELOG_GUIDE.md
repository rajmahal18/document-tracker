# Changelog Guide for AI

When updating changelogs:
1. Do not create a new version for tiny fixes.
2. Put small fixes under [Unreleased].
3. Create a new version only when the user says release, deploy, milestone, or version bump.
4. Use user-facing language, not raw commit language.
5. Group changes by Added, Changed, Fixed, Removed.
6. Always include Affected Areas for DTS-related changes.
7. Mention breaking changes clearly.
8. Never exaggerate. If uncertain, say "Internal cleanup" or ask.
